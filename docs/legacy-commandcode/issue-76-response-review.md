# 问题 #76：账号响应诊断修复

## 一、已确认的问题

1. [问题 #76](https://github.com/Mars-Sea/dsh-commandcode-provider/issues/76) 的截图显示四个账号接口均收到 HTTP 200，但无法取得可用正文。截图不足以判断聊天中断、密钥失效、额度耗尽或解压失败。
2. 原 `fetchJson()` 统一捕获 `response.json()` 的异常，丢弃正文读取超时、中断与解析失败的区别。返回合法 JSON 但顶层不是对象时，也显示相同的格式错误。
3. `Accept-Encoding: identity`（要求未压缩正文）已在源码和构建产物中生效；本轮未复现反馈者的真实代理或提供商环境。

## 二、修复范围

1. 正文读取、JSON 解析和顶层对象校验分别诊断。收到响应后的读取失败保留 HTTP 状态，区分超时和中断。
2. 安全诊断仅保留白名单异常名称、错误码、内容类型和编码；不记录正文、原异常消息、密钥或任意响应头。异常因果链读取有深度上限，并防止循环。
3. 整组响应不可用仍沿用 `invalid-response`，详情通过既有 `failures` 文本传递；不增加远端报告字段或枚举，不改变账号健康标记、轮换和聊天重试策略。
4. 内容类型／编码仅供排查；已可解析的正文不因头部标记被拒绝或再次解压。设置页、用量面板和命令使用中性提示，不把所有故障归因于代理或解压。

## 三、验证

1. 回归覆盖收到 HTTP 200 后的连接重置、正文读取超时、HTML 网页正文、JSON 截断、非对象顶层、私密数据隐藏、环形异常链，以及带字节顺序标记的已解码 JSON。
2. 针对性测试 15/15、全套测试 906/906、`npm run typecheck`（类型检查）、`npm run build`（构建）与差异格式检查通过；已检查生成的 `lib/` 包含新诊断和提示。
3. 沙箱内首次全套测试有 25 项登录回调用例无法绑定本地端口；允许环回端口后原样重跑，全套通过。测试使用合成响应，未访问真实账号。

## 四、证据边界

1. 本轮修复已确认的错误诊断，不代表已消除反馈者环境中的响应故障。合成响应测试不能替代真实账号和代理验证。
2. 后续失败详情可区分正文读取问题、格式问题和编码线索；缺少原始响应时不自动猜测 Brotli 压缩或调整宿主代理配置。
