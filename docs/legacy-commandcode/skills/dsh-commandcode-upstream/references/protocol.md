# Protocol and account verification

Read saved changelog/What's New and inspect actual CLI call sites, comparing pinned and latest bundles where available. Named endpoint strings alone do not establish unchanged behavior. The current transport contract is in repository AGENTS.md and adapter tests; use those as the local comparison surface.

Account for these paths explicitly:

- Legacy `POST /alpha/generate`: `{ config, memory, taste, skills, permissionMode, params: { model, messages, tools, system, max_tokens, temperature, stream, reasoning_effort? }, threadId, mode, promptCache }`; UUID thread ID and version header; native CLI base64 image shape. Reasoning IS replayed in later turns as a `{ type: 'reasoning', text }` assistant block — the official CLI's `toWireMessages` converts every `thinking` block that way, and a DeepSeek thinking-mode tool loop is rejected without it (issue #34); `toWireTools` passes each `input_schema` through untouched, so the object-root constraint is this plugin's to enforce (issue #35). `mode` and `permissionMode` are each validated against a fixed server-side enum (confirmed 2026-09-30 by a live 400 on a bogus value): `mode` accepts `agent | learning | custom-agent | custom-agent-create | title-gen | tool-desc | compact | vision | …` (the full list was truncated in the one rejection observed — re-check with a longer bogus value before treating this as exhaustive), `permissionMode` accepts `default | standard | auto-accept | plan | bypass`. Both are accepted as absent (no 400, and a repeated live A/B on a free model found no response-shape difference either way) — `mode`'s value for an ordinary agent-loop turn was not pinned down from static reading (it comes from an agent-loop-level config object, not a literal); `permissionMode`'s real wire value for a default session is `"standard"` (the CLI's internal default `"default"` is normalized by `toWirePermissionMode()` before serialization, not sent literally). `promptCache` is never set by the normal agent-loop turn either — only isolated side calls (image description, compaction, title generation) send it, always `"off"`; do not add a client-side guess.
- Provider `POST /provider/v1/chat/completions`: OpenAI request/image format, historical `reasoning_content`, object-rooted tool `parameters` (the same normalization as above), `upgrade_required` fallback to the CLI transport. This endpoint need not appear verbatim in the CLI bundle; inspect official Provider docs as well.
- Streaming: CLI text/reasoning/tool/finish/error events and OpenAI deltas/usage. Preserve declared semantics, block start/end pairing, raw tool JSON, usage before finish and no chunks after finish. Only paired tool/result history is replayed. Do not infer reasoning from ordinary text.
- Catalog `GET /provider/v1/models`; default API base; `x-command-code-version`; model-specific option handling.
- `GET /alpha/whoami`, `/alpha/usage/summary`, `/alpha/billing/credits`, `/alpha/billing/subscriptions`: org ID, status acceptance (`active`, `trialing`, `past_due`), credits-plan fallback and on-demand bypass behavior.
- `POST /alpha/web-search`: query/count/domain filters, headers, response mapping and error taxonomy. No real search request is needed for static extraction.
- Browser login: Studio `/studio/auth/cli`, loopback port selection, callback URL, POST `/callback` JSON fields, state validation, origin/CORS rules, timeout/cancel cleanup and `/alpha/whoami` validation. Keep stored credentials on the Host. Review private versus remote-Host assumptions.
- Auth-file format: `~/.commandcode/auth.json`, existing credential precedence; never scan pi/OMP files. Reading bundle code does not require accessing local credentials.
- Account rotation/retry: pre-stream rejection only, per-key state, deadlines, rate-limit wait hints and no mid-stream rotation. Do not alter these during a data-only sync.

Public evidence and local tests support a static compatibility assessment, not proof of live behavior. If authenticated validation is needed and within the user's authorized scope, use targeted probes with stated cost/coverage. Do not sweep every model by default. A successful request does not prove the minimum plan because paid credits can bypass plan restrictions; a 403 may give useful tier evidence, but other errors are not tier evidence.

When reporting, distinguish “static call sites checked”, “local tests passed” and “live behavior verified”. Mark unsupported conclusions unknown. User authorization for the scoped work persists; do not introduce a new approval merely to inspect public code.
