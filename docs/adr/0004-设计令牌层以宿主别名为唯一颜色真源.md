# ADR-0004：设计令牌层以宿主别名为唯一颜色真源

- 状态：已采纳
- 日期：2026-10-22
- 关联：`docs/opendesign/03-spec.md`、`docs/adr/0002-不显示金额只留成本档位.md`

## 背景

外部设计体系（Open Design 生成的 brand package，本轮为 `DeepSeek-Harness`，上一轮同名内容叫 `Product`）
提供三层 token：primitive → alias → specific，并附明暗双主题与 compact 密度档。它的强项是**度量与规则**
（8px 基线网格、4/8/12/16 圆角阶梯、控件高阶梯、状态必须同时给文字与图标、一个视口一个实心主操作），
弱项是颜色：它的调色板来自一份 `designmd://` 粘贴的 seed，与宿主无关。

同时，宿主 DSH 已经有一套运行时注入的 `--dsw-alias-*` 调色板（`dsh-client-ui-theme` 的 `ThemeRuntime`
在 `<body>` 上写 CSS 变量，`body[data-ds-dark-theme]` 整体切换暗色）。这套别名覆盖亮暗两套 101 个语义
令牌，并且是宿主所有原生控件（Button / Input / Switch / DisclosureRow）的唯一取色路径。

如果我们把设计体系自带颜色搬进来当唯一真源，会出现两个后果：

1. **与外壳冷暖不一致**：插件四块界面嵌在宿主设置弹窗里，两侧背景与描边必须同源，否则一眼能看出是外挂。
2. **暗色要自己维护一套映射**：宿主的暗色不是"把亮色调暗"，而是换了一组 static 令牌，手抄会持续漂移。

## 决策

**颜色只有一条真源：宿主 `--dsw-alias-*`。设计体系负责度量、形状与姿态规则，宿主负责颜色。**

具体边界：

| 维度 | 真源 | 说明 |
| --- | --- | --- |
| 颜色（文字/背景/描边/状态/强调） | 宿主 `--dsw-alias-*` | 组件样式不写十六进制与 rgba |
| 间距、字阶、行高、圆角、控件高、动效 | 设计体系 | 收进插件自有令牌层（见下） |
| 控件形状与状态规则 | 设计体系 | 4/8/12/16 圆角阶梯、999px 仅用于胶囊元素 |
| 品牌信号色归属 | 宿主 | 见下节「强调色」 |

### 强调色：`state-business-primary` 而不是 `brand-primary`

这是本次刷新发现的**真缺陷**，不只是风格问题。宿主里两个别名的含义与名字相反：

| 别名 | 亮色解析 | 暗色解析 | 宿主语义 |
| --- | --- | --- | --- |
| `--dsw-alias-brand-primary` | `#0f1115`（近黑） | `#f9fafb`（近白） | **单色**，与 `label-primary` 同值；用于"反色块" |
| `--dsw-alias-state-business-primary` | `#4176e6`（蓝） | `#7aaaff`（亮蓝） | 真正的品牌强调蓝 |

插件此前把 `brand-primary` 当作强调蓝用于进度条填充、开关选中态、焦点环与徽标文字 —— 在真实宿主里这些
位置其实是**近黑/近白**，所以进度条与开关看起来像"无色的灰条"。预览工具里把 `brand-primary` 样例值写成
蓝色，正好把这个错误掩盖了（见 ADR 附注）。

**决策**：所有"需要颜色识别"的位置改用 `state-business-primary`（进度条填充、焦点环、徽标文字、选中边框），
`brand-primary` 不再用于这些位置。

**例外（显式决定，不是遗漏）**：**选中态的填充**保持单色 —— 复选框用 `label-primary` 填充、
开关选中用 `label-primary`，前景用 `label-primary-foreground`。理由是宿主自身的原生控件就这么画：
`Checkbox.module.css` 用 `accent-color: var(--dsw-alias-brand-primary)`（在本宿主里解析为单色近黑/近白），
`Switch.module.css` 选中态用 `var(--dsw-alias-brand-primary)`。插件若把选中态改成蓝色，就会和旁边同屏的
原生复选框/开关不一致；而设计体系对 accent 的用法限定本来就是"描边、焦点与非文本强调"，
选中态填充是**反色块**语义，属于单色范畴。

### 插件自有令牌层

新建 `src/client/tokens.ts`，导出两段 CSS：

- `TOKEN_CSS`：在**插件自己的类作用域**上定义 `--od-*` 令牌（`--od-space-*`、`--od-radius-*`、
  `--od-control-*`、`--od-font-*`/`--od-leading-*`、`--od-motion-*`、`--od-focus-offset`、`--od-bar-h`），
  值里可以引用 `--dsw-*` 别名。令牌名以 `src/client/tokens.ts` 为准；本 ADR 早期草稿写的
  `--od-control-h*` 未落地，特此更正。
- 不写 `:root`：`tests/styles.test.ts` 的隔离契约要求每条选择器必须锚定在 `od-`/`odp-` 上；
  往 `:root` 写全局变量会污染宿主，也不符合"插件只碰自己"的既定约束。

令牌层是**单一事实来源**：`page-styles.ts` 与 `panel-styles.ts` 都只引用 `--od-*`（度量）与
`--dsw-alias-*`（颜色），不再出现散落的 `12px` / `8px` 之类度量字面值。

### 密度：取 compact 档而不是 default 档

设计体系的 default 控件高 44px，那是独立桌面外壳的规范；compact 档是同一 seed 跑出的密集算法
（控件 28px）。插件界面是宿主设置弹窗里的一页密集列表，必须与宿主原生控件同量级
（宿主 Input 32px、Switch 36×20、Button md 36px / sm 28px、DisclosureRow 24px）。

**决策**：以 compact 为基准，并显式定三档：`--od-control`（32px，输入类）、`--od-control-lg`
（36px，主操作）、`--od-control-sm`（28px，次级）。这与宿主原生阶梯一一对齐，也解释了为什么不取 44px。
另有 `--od-bar-h:44px`，那是保存条这个浮层容器自身的高度，**不是控件档**——这几个界面里没有任何控件高 44px。

### 描边：保留宿主 0.5px 发丝线

设计体系写 1px 描边；宿主原生控件统一 0.5px（`Input.module.css`、`Button.module.css` 均为 `0.5px`）。
描边粗细属于"与宿主同框"的容器事实，**取宿主值 0.5px**；圆角与形状取设计体系阶梯。

## 后果

- 暗色模式**零额外成本**：别名已由宿主切换，插件不写任何 `[data-...-dark]` 选择器。
- 设计体系的颜色部分（`tokens.dark.json`、`variables.dark.css`）**不进入代码**，只作为度量与规则来源。
- 若将来宿主调色板变化，插件自动跟随，不会出现"插件还是旧蓝"的漂移。
- 新增 `tests/tokens.test.ts`：断言令牌层不含 `:root`、不含十六进制颜色、且每个 `--od-*` 都被至少
  一处使用（防死令牌）。

## 附注：预览工具必须与真实宿主同源

`scripts/preview/app.tsx` 里的 `THEME_TOKENS` 是手抄的样例值，此前把 `--dsw-alias-brand-primary`
写成了 `#3b82f6`（蓝），而宿主真实值是近黑 —— 这让"进度条是蓝色"的假象在预览里成立，掩盖了上面那条
真缺陷。**决策**：预览样例值改为从真实宿主解析结果抄录（记录在 `tests/tokens.test.ts` 的夹具里），
并对 `brand-primary` 与 `state-business-primary` 分别给出真实值，避免再次掩盖。

## 补记（同轮实现中新增的两条证据）

### 1. 圆角阶梯：设计体系没有胶囊档

设计体系 `DESIGN.md` §Layout 的圆角阶梯是 8px 默认、4px 标签与菜单项、12px 卡片、16px 对话框、
28px 仅整窗；其组件展示页（`system/kit.html`）内联样式实测只出现 `4px`、`5px`、`8px`、`10px`、`12px`、`50%`，
**没有任何 999px 胶囊**。

插件此前在 14 处把按钮、下拉触发器、徽标、保存条做成 999px 胶囊；宿主自身的 Button 是
`--dsw-radius-md`(12px) / `--dsw-radius-sm`(8px) 矩形，Input 是 12px 矩形。也就是说胶囊是**两边都不属于**
的形状，是"看起来不像这套体系"的最直接来源。

**决策**：按设计体系阶梯落地——徽标 4px、按钮/输入/下拉 8px、卡片与浮层 12px；
仅开关轨道与进度条保留胶囊（那是控件自身的形状，不是组件圆角）。

### 2. 主操作实心按钮的配色受宿主可读性约束

设计体系要求"实心主按钮用 accent-secondary（`#0958d9`，6.16:1）"，而 `#1677ff`（accent）只用于
描边、焦点与 24px 以上大字（4.10:1，正文不可用）。

宿主**没有**对应 accent-secondary 的别名：它唯一的蓝色是 `state-business-primary` / `button-info-fill` /
`link`，取值 `#4176e6`（亮）/ `#7aaaff`（暗）。`#4176e6` 上放白字实测对比度约 4.19:1，低于正文 4.5:1 的
下限；宿主的实心主按钮（`button-primary-fill`）本身是单色（`#0f1115` / `#f9fafb`），对比度 17:1 以上。

**决策**：实心主操作取宿主 `button-primary-fill` + `label-primary-foreground`（AA 安全、与宿主原生按钮同源）；
蓝色只用于非文本强调（进度条填充、焦点环、徽标文字、选中边框），这正是设计体系对 accent 的用法限定。
若将来宿主提供可读深阶蓝（≈6:1），再把主操作换成它即可，组件侧无需改动。
