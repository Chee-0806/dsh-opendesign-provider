## 4. 协议层（P0）

### 4.1 传输选择

默认实现 **OpenAI Chat Completions**：`POST {apiBase}/chat/completions`。保留 `LlmAdapter` 内的传输接缝（一个 `buildBody`/`parseStream` 组合）；**不做** Responses（DSH 每次发全量历史，`previous_response_id` 无价值）。

P2（ticket 13）在这个接缝上加了可选的 **Anthropic Messages** 传输（`POST {apiBase}/messages`，必带 `anthropic-version: 2023-06-01`，请求体为 Anthropic 形态，不发 Chat 字段），选路由 Config `protocol` 决定：

- `auto`（默认）：只让 `claude-haiku-5.5` 走 Messages（它在 Chat 面看不到思考，且 Messages 面显式开 `thinking` 后思考可读）；其余模型继续走 Chat，默认路径与 P0 完全一致。
- `chat` / `messages`：用户显式指定，强行统一一面（`messages` 失败如实报错，不静默换面）。
- `auto` 下的协议错误/不支持回落 Chat 一次并按模型记住偏好，回落不中断对话。

实测更正（2026-10-21）：`gpt-6-luna` 在 Messages 面只回 `redacted_thinking`（加密块），思考不可读，故**不**入自动选路；细节见 `docs/adr/0001-只做Chat-Completions单传输.md` 的补记。

### 4.2 请求构造

- `model`：目录 id。
- `messages`：DSH 角色映射；`supportsDeveloperRole: false`（路由级）→ `developer` 一律降级为 `system`（glm 实测 400，其余模型未被拒；统一降级是保守选择）。
- `tools`：`[{type:'function', function:{name,description,parameters}}]`（OpenAI 形态）。
- `stream: true`、`stream_options: {include_usage: true}`。
- `max_completion_tokens`：见 §4.3。**不发 `max_tokens`**（实测全员不认，且可能被当成别的语义）。
- `reasoning_effort`：见 §4.4；`off` 发字面量 `"none"`。
- `temperature`：默认不发（上游行为未验证，DSH 默认值不强行透传）；如需透传走设置项，默认关。
- `store`：不发（网关默认 true，属服务端行为；本插件不需要回放）。

### 4.3 输出上限与客户端硬截断

- 请求上限 = `min(DSH 预算, output_budget, 262144)`，用 `max_completion_tokens` 发送。
- **硬截断**：适配器累计 `completion_tokens`（含 reasoning token）达到上限即主动结束读取，以 `finish_reason: length` 收尾，并保留已收到的内容。理由：deepseek/glm 实测不遵守该字段（16 → 232），kimi 的 `medium/high` 档需要 `max_completion_tokens > thinking_budget`（low 8192、medium 32768）。
- kimi 特例：`output_budget` 32000 < 32768，`maxTokens` 抬到 65536；`max_completion_tokens` 必须 > 该档 thinking_budget。

| 模型组 | 支持的档位（DSH 枚举） | 映射规则 |

### 4.5 流解析

- `choices[].delta.content` → 文本增量。
- `choices[].delta.reasoning` / `reasoning_details` → 思考增量（**字段名是 `reasoning`，不是 `reasoning_content`**）；容忍首帧空串（deepseek 会先发 `reasoning:""`）。
- `choices[].delta.tool_calls[]` → 按 index 累积 `id/name/arguments`，流结束时组装；`finish_reason` 缺失时**以 `tool_calls` 是否存在判定工具调用**。
- `finish_reason`：**可缺省**（gpt-6-luna 非流式缺失、流式存在）；缺省时按「有内容收尾=stop、达上限=length、有 tool_calls=tool_use」推断。
- 尾帧 usage：`choices: []` 且带 `usage` 的帧必须计入（`prompt_tokens_details.cached_tokens`、`completion_tokens_details.reasoning_tokens`）；读不到时按已解析内容估算并标注「缺失」。
- `[DONE]` 为协议终止标记；同一包后续事件不再解析。
- 空流：HTTP 200 但流里既无正文、思考、工具调用，也无内容可展示 → `EMPTY_RESPONSE`（可重试，与「网关没按协议回话」的 `PROTOCOL_ERROR` 分开）。
- 流空闲超时：`streamIdleTimeoutMs`（默认 300 秒）已接入，半路停止写入即中止读取并报 `TIMEOUT`；与「首字节请求超时」分开，避免一轮对话等一个永远不来的 token。

### 4.6 错误三态与分类

| 场景 | 形状 | 处理 |
| --- | --- | --- |
| 401 | JSON `{"error":{"code":"invalid_api_key","message":"…","type":"invalid_api_key"}}` | `AUTH`，不可重试，文案指向「创建/检查 API Key」 |
| 400 上游拒绝 | JSON `error.code = upstream_error`，真因在 `message` 的 `[code=…]` 前缀 | 解析真因；`Incorrect role information`（glm + developer）、`Empty input messages`、`Previous response…` 等为确定性错误，**不重试**；对外错误码是 `BAD_REQUEST`（实现命名，取代早期设计里的 `DETERMINISTIC_BAD_REQUEST`） |
| 402 | 额度耗尽（web 侧记录「所有 /v1/chat 返回 402」） | `QUOTA_EXHAUSTED`，不可重试，文案指向控制台额度页 |
| 502 包 400 | 网关把上游 400 包成 502 | 解析 body：含 `upstream_error` 且真因为确定性 → 归 `BAD_REQUEST`，**不重试**；读不出确定性原因 → `TRANSIENT` 按临时故障重试 |
| 404（非 JSON） | `text/plain` 的 `404 page not found` 或 nginx `text/html` | `PROTOCOL_ERROR`，不解析 JSON，文案指向 `apiBase` |
| 404（JSON） | 实测 `{"error":{"code":"model_not_found",…}}` | 归 `BAD_REQUEST`（模型 id 不对，确定性），不重试 |
| 200 空流 | 流里没有任何可展示内容 | `EMPTY_RESPONSE`，可重试（与 `PROTOCOL_ERROR` 分开） |
| 流空闲超时 | 连上后上游停止写入 | `TIMEOUT`，中止读取并提示可调大 `streamIdleTimeoutMs` |
| 429 | 形状未验证（探测未触发，无 `x-ratelimit-*`） | `RATE_LIMIT`；有 `Retry-After` 用，无则退避，次数由重试预算约束 |

**`TRANSPORT` 与 `TRANSIENT` 的分工**（贯穿适配器与 Host 重试）：

- `TRANSIENT` 是「拿到了 HTTP 响应、状态是 5xx、且读不出确定性原因」的上游临时故障，交给引擎的
  `providerRetryPolicy` 包内重试，次数由 `src/transient-retry.ts` 的预算约束。
- `TRANSPORT` 是「连接根本没建立成功」的传输层失败（DNS/TLS/reset/连接超时），由
  `src/transport-retry.ts` 单独预算，避免一次 10 秒连接超时被当成普通 5xx 拖成数分钟。
- 两者都在可重试集合里，但预算是各自独立计数的；`AUTH`/`QUOTA_EXHAUSTED`/`BAD_REQUEST`/`PROTOCOL_ERROR`
  不在集合内，重试同一请求只会得到同一个结果。

### 4.7 图片

- 目录 `architecture.input_modalities` 含 `image` → 允许图片；用通用 `image-request.ts` 目标（长边 1568 / 编码 1 MiB）与 `image-tokens.ts` 估算。
- `file` / `audio` / `video` 模态**不接**：DSH 若送来这类附件，报 `UNSUPPORTED_CONTENT` 并说明「Open Design 该模型仅支持 text/image」。
- 图片输入已实测：`deepseek-v4.1-flash` 收到 16x16 PNG 能正确描述内容（ticket 07 / 09），不再列为未验证项。
- 视觉 token 估算按模型家族（`claude*`→anthropic、`gpt*`/`o1..o9`→openai、`google`/`gemini`→google、
  `deepseek`→deepseek）。**裸 id（不含 `/`）一律按 `generic` 保守规则**，不猜厂商；这是估值不是账单，
  实际用量仍以上游 usage 为准。

### 4.8 明确不支持

## 5. 目录与静态快照（P0）

### 5.1 解析规则

- 请求：`GET {apiBase}/models`，`Authorization: Bearer`，超时 10s。
- 校验：`{object:'list', data:[…]}`；单条 `id`（string）、`enabled`（bool，默认 true）、`default`（bool）。
- 字段映射：
  - 上下文窗口 = `metadata.context_budget`（**不是** `context_limit`）→ 缺省回落 `context_limit`，再缺省 `128000`。
  - 输出上限 = `metadata.output_budget`（缺省 `32768`）；kimi 特例 65536。
  - 视觉 = `architecture.input_modalities` 含 `image`。
  - 档位 = `metadata.cost`（low/medium/high）、`metadata.capability`（standard/advanced）。
- 缓存：`~/.opendesign/models-cache.json`，含 `apiBase` 与版本号；TTL 5 分钟，失败重试 TTL 10 秒。

## 6. 凭据链与配置（P0）

### 6.1 解析优先级

1. `config.apiKey`（字面量，secret 角色，`redactSecrets` 剥离）。
2. `config.apiKeyEnv` 指定的凭据引用（默认 `OPEN_DESIGN_API_KEY`）。

> 实测更正（P0 验收）：`vela login` 写入的 `linkUrl` 是**模型面主机名**，不带 `/v1`
> （本机为 `https://amr-link.open-design.ai`；`/models` 会得到 nginx HTML 404，`/v1/models` 才是 200）。
> 因此 `src/credentials.ts` 的 `cliLoginApiBase()` 在裸源站（path 为空或 `/`）后补 `/v1`；若服务端下发的
> `linkUrl` 自带路径则原样使用。ticket 09 的 live 脚本正是先在这里失败、修复后才跑通目录与全部模型用例。

控制密钥（P1 额度）：`~/.amr/config.json` 的 `controlKey`；缺席时额度功能整体降级（面板隐藏、命令提示「需要 OpenDesign CLI 登录态」），不影响推理。

不支持多账户轮换（OpenDesign 是单 key 模型；多账户票不开）。

## 8. 额度（P1）

### 8.1 控制面事实（本机实测）

- `GET {apiUrl}/api/v1/workspaces/current` → `activeWorkspaceId`、`personalMembershipTier`、`workspaceType`。
- `GET {apiUrl}/api/v1/billing/summary` → `membershipTier`（go）、`balanceUsd`（字符串）、`creditsPerUsd`（10000）、`balances.*`、`subscriptionStatus`、`subscriptionCurrentPeriodStart/End`、`usageCount`。
- `GET {apiUrl}/api/v1/workspaces/{id}/billing/preflight?model={id}` → `codingPlan.eligible`、`codingPlan.tier`、`codingPlan.windows[]`（`durationSeconds` 18000=5h / 604800=7d、`usedCredits`、`limitCredits`、`remainingCredits`、`windowStart`、`resetsAt`、`resetMode`）、`balanceUsd`、`funding`（`wallet` / 计划额度）。
- 头：`Authorization: Bearer <controlKey>`；Node `fetch` 实测 200（Python urllib 被 Cloudflare 1010 拦，**不要用非 Node 客户端探针**）；不发 `anthropic-version`。

### 8.2 数据模型

```
QuotaSnapshot {
  controlPlaneAvailable: boolean
  tier?: 'go'|'plus'|'pro'|'max' | string
  subscriptionStatus?, currentPeriodEnd?
  balanceUsd?: number
  funding?: 'wallet' | 'coding_plan'
  windows: Array<{ kind:'five_hour'|'seven_day', usedCredits, limitCredits, remainingCredits, resetsAt, resetMode }>
  fetchedAt
}
```

- 窗口按 `durationSeconds` 分类（18000/604800），未知时长原样列出。
- 金额换算：`credits / creditsPerUsd`，只用于展示已用/上限的 USD 当量（额度窗口本身是 credits）。
- 缓存：Host 侧 60 秒；面板打开时刷新；失败保留上次值并标注「数据过期」。

### 8.3 面板与命令

- 侧栏卡（默认关，`showSidebarQuota`）：套餐档位 + 7 天窗口进度 + 5 小时窗口（仅 Go 有）。点击打开中间栏仪表盘：两个窗口的进度条、重置时间、钱包余额、订阅周期、额度口径说明（Design Plan 先扣、5h 仅 Go）。
- `/opendesign`：文本看板（同数据），TUI 安全。
- 降级：无 `controlKey` → 面板不渲染、命令提示原因；`eligible:false` → 显示钱包计费说明。
