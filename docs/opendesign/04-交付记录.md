## 思考档位修正：DeepSeek 只有 3 档 + 关闭（2026-10-21 深夜）

**反馈**：模型下拉的「推理等级」给 DeepSeek 列出了 8 项（Default / Off / Minimal / Low / Medium /
High / Extra high / Max），而 DeepSeek 官方只支持三档。

**根因**：`catalog-snapshot.ts` 把这 4 个 DeepSeek 模型挂在 `ALL_LEVELS` 上，依据只是「网关对 7 个
`reasoning_effort` 值都回 200」。但 200 只证明字段被接受，不证明档位存在——网关对 DeepSeek 是原样
透传，真正的映射由 DeepSeek 上游完成。

**三源交叉验证**（详见 `docs/grill/20261020-opendesign-facts-local.md` §5.2）：

| 来源 | 结论 |
| --- | --- |
| DeepSeek 官方[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)映射表 | 真实档位 low / high / max；`minimal→low`、`medium/high/xhigh→high`、`ultra→max`；思考默认开、默认 `high` |
| Command Code 官方 CLI 快照（`KNOWN_EFFORTS`） | `deepseek/deepseek-v4.1-flash → ["off","low","high","max"]` |
| 社区 `opencode-opendesign-auth@0.1.4` | 根本不枚举档位，只按 `capability` 给布尔 `reasoning` |
| 本机实测（`reasoning_tokens` × 6 中位） | `v4.1-flash` low 1592 < high 1910 < max 2434；`v4-flash` 240 < 286；`v4-pro` 275 < 361，单调可区分 |

> Command Code 快照给 `v4-flash` / `v4-pro` 只写了 `["off","high","max"]`（无 `low`），但实测它们接受
> `low` 且显著更轻，所以按 4 档处理——这是「快照与实测冲突以实测为准」的一处，已记在事实基线里。

**改动**
- `src/catalog-snapshot.ts`：新增 `DEEPSEEK_LEVELS = ['off','low','high','max']`，4 个 DeepSeek 模型改挂它。
- `src/quirks.ts`：新增 `DEEPSEEK_LEVEL_FOLDS`（`medium→high`）与 `hasDeepSeekDomain()`。**不能复用 glm 的
  `COARSE_LEVEL_FOLDS`**——glm 的 `medium→low` 与 DeepSeek 官方 `medium→high` 方向相反；凡上游公布了
  映射的照上游走。
- `scripts/verify-live.mjs` case3 改为断言 4 档 + 逐个真实请求 + 别名折叠断言。
- 文档：设计件 §4.4 档位表与 §7 域收敛行、事实基线 §5 表格（4 行）+ 新增 §5.2。

- `npm run typecheck` / `build` / `test:pack` / `test:engine`（2 引擎）/ `test:install`（2 引擎）/ `test:live`

## 上下文窗口修正：`context_limit` 而不是 `context_budget`（2026-10-21）

**问题**：用户问「上下文长度呢，opendesign 返回吗，deepseek 官方是 1m 上下文」。查下来两个都对：
网关**确实**返回上下文长度，DeepSeek 的 1M 也**确实**可用；是插件报错了——原设计把
`metadata.context_budget` 当窗口，而它只有真实额度的 22%~38%。

**为什么会错**：`docs/grill/20261020-opendesign-facts-web.md` §4.1 有一句「`context_budget` 是输入预算，
`output_budget` 是回答上限，二者都小于 `context_limit` —— 这点很重要，不要把 `context_limit` 当可用上下文」。
这是从字段名做的**推断**，从没有实测过，却被设计件 §5.1 与 spec 当成了硬规则。

**实测（真实 Key，全部 200）**：

| 模型 | budget | limit | 实际 prompt_tokens | 结果 |
| --- | --- | --- | --- | --- |
| `deepseek-v4.1-flash` | 328000 | 1048000 | 200747 / 602155 / 802842 | ✅ 三次大海捞针全部正确召回 |
| `claude-haiku-5.5` | 228000 | 1000000 | 493393 | ✅ |
| `gpt-6-luna` | 400000 | 1050000 | 432790 | ✅ |
| `hy4-preview` | 232000 | 1048000 | 251039 | ✅ |
| `mimo-v2.6-flash` | 232000 | 1048000 | 242656 | ✅ |

拒绝边界贴着 `context_limit`：`deepseek-v4-flash` 在 1031177 可行、**1048383 被拒**（`context_length_exceeded`）；
`kimi-k2.7-code`（limit=budget=262000）越界报 `Range of input length should be [1, 262144]`。

**决定性证据（计数口径）**：同样 ~1044000 tokens 输入，`max_completion_tokens=16` → **200**
（prompt_tokens=1047688）；改成 `max_completion_tokens=32768` → **400**。证明 `context_limit` 的分母是
「输入 + 输出」，与宿主 `LlmModelContext.contextWindow` 的官方定义
「Maximum combined request and response context」逐字吻合。**这才是该上报的值，不是"更宽松"的妥协。**

**改动**
- `src/gateway-facts.ts`：`contextWindow: fact.contextLimit ?? known?.contextWindow ?? DEFAULT_CONTEXT_WINDOW`；
  `context_budget` 仍解析保留（作证据），不再参与窗口计算；docblock 写入完整探针依据。
- `src/catalog-snapshot.ts`：12 条 `contextWindow` 换成 `context_limit`（228000→1000000、232000→1048000、
  328000→1048000、400000→1050000 等），头部注释改正。
- `tests/catalog-live.test.ts`：新增回归断言——同时给 `context_limit=64000` 与更小的
  `context_budget=9000` 时必须取 64000，防止有人再接回去。
- 文档：设计件 §5.1/§5.2 表格、spec §3、事实基线 §5 表头 + 新增 §5.3、web 事实基线 §4.1 加删除线更正。

**验证**
- `npm test` **370/370**；`typecheck` / `build` / `test:pack` / `test:engine` / `test:install` 全绿；
  `test:live` **8 PASS / 0 FAIL / 3 SKIP**。
- 装进 web profile 后直接调已安装产物的 `resolveModel`，12 个模型上报值全部正确
  （deepseek/glm/hy/mimo 系 1048000、claude 与 glm-flashx 1000000、gpt-6-luna 1050000、kimi 262000）。

**顺带发现（本轮未改，单列）**：`output_budget` 同样不是硬上限——`v4-flash` 的 32000 仍接受
`max_completion_tokens=64000`/`128000` 并 200。当前 `maxTokens` 映射取 `output_budget`，报小不会丢数据
（只是默认回答偏短），是否抬高需单独评估（牵涉 kimi 的 thinking_budget 门限特例），不与本修正捆绑。

`dsh plugin add` 本体是透传 `pnpm add`，所以它天然支持 npm 包名 / git 仓库 / tarball / 本地目录四种来源。

  密钥字面量与被跟踪文件，无敏感内容；`.opendesign/`、`.scratch/`、`*.tgz` 均已在 `.gitignore`）。

  `git diff -- lib/` 为空），git 安装不再触发安装期脚本，无需白名单。
