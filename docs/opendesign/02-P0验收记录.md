## 5. 偏差与更正

### 5.1 本票修掉的真实缺陷（live 首跑发现）

- **CLI 登录态的 `linkUrl` 是主机名，不带 `/v1`。** 首跑 case 1 目录回落 `static`（reason `http`）：插件按
  `{apiBase}/models` 请求 `https://amr-link.open-design.ai/models`，得到 nginx HTML 404；实测
  `https://amr-link.open-design.ai/v1/models` 才是 200。原实现直接把 `linkUrl` 当 apiBase（ticket 08 的测试
  夹具假设它自带 `/v1`，与真实登录态不符）。
  修复：`src/credentials.ts` 新增 `cliLoginApiBase()`，裸源站（path 为空或 `/`）补 `/v1`，自带路径原样保留；
  新增 `tests/credentials.test.ts` 用例覆盖主机名、尾斜杠、自带路径三种形状；设计件 §6.1 与 spec 同步更正。
  这是本票唯一的业务代码改动，其余都是文档/元数据/脚本。

### 5.2 设计件口径更正（实现与设计不一致处，已回写）

- 错误码 `DETERMINISTIC_BAD_REQUEST` → 实现名 **`BAD_REQUEST`**；404 带 JSON（`model_not_found`）归
  `BAD_REQUEST`，404 纯文本/HTML 才是 `PROTOCOL_ERROR`；200 空流为 **`EMPTY_RESPONSE`**（可重试）。
- **`TRANSPORT` vs `TRANSIENT`**：前者是连接没建立（独立重试预算，`transport-retry.ts`），后者是拿到 5xx 但
  读不出确定性原因（引擎重试策略 + `transient-retry.ts`）；两者都在可重试集合，预算各自独立。
- `streamIdleTimeoutMs` 已接入（默认 300s，半路停止写入即中止并报 `TIMEOUT`），不再是「待接」。
- `image-tokens` 对不含 `/` 的裸模型 id 一律走 `generic` 保守规则，不猜厂商。
- 设计件 §10.3 case 5 原文写 `finish=length`；实际对外 finish 种类是适配器的 **`max-tokens`**（对应 HTTP
  `finish_reason: length`），已在 §10.3 更正。
- 设计件 §10.3 case 6 原写「glm + developer 强制 400」；实现把 `developer` 统一降级为 `system`，真机不可
  构造该 400，live 改为三条可构造路径（假 Key / 错误 apiBase / 不存在模型），分类细节由单测覆盖。

### 5.3 验收过程中的脚本侧问题（非插件缺陷）

- 图片用例初次给 `maxTokens=256`：视觉模型的思考也计入输出上限，思考吃满后正文被截断；改为 1024 后稳定
  返回「红色 蓝色」。这是验收用例的预算设置，不是插件行为问题。
- `LlmError` 的 HTTP 状态在 `failure.status`，不在 `error.status`；脚本已按真实形状断言。

### 5.4 元数据与文案

- `locale/zh.json` 的 `meta.title` 由「Open Design 提供方」改为 `Open Design`，与显示名、`en.json` 对齐；
  两份 description 去掉了「Design Plan 额度」这一 P1 尚未交付的能力描述。
- `package.json` 的 description 同步去掉额度承诺，改为 P0 实际能力。
- `icon` 字段保持缺失（不伪造品牌资产），README 两版均注明「暂无插件图标，待设计稿」。
- `NOTICE` 保留 Mars-Sea / pi 上游与 Command Code 的 MIT 归属，新增 Open Design / Powerformer 的非关联声明。
- 新增 `npm run test:live` 脚本别名，README 的验证段与之对齐。

## 6. 未验证项与遗留

1. **设置页浏览器交互**（密钥写入/清除、apiBase 修改、可见模型过滤、上下文覆盖的实际界面效果）：本票只做到
   单测与 live 装配验证；由维护者在真实 desktop profile 中人工验收。
2. **真实 profile 安装与 Command Code 共存**：由维护者在本票合并后执行（`npm pack` → `dsh plugin add` →
   重启 → 设置页/模型卡可见、与 `@mars-sea/dsh-commandcode-provider` 并存）。本票不碰用户的
   `~/.dsh/profiles/desktop`。
3. **429 / `Retry-After`**：实现与单测齐全，live 未触发限流；无 `x-ratelimit-*` 头可依赖。
4. **`temperature`、`stop`、`logprobs`**：默认不发/不支持，行为未在真机校准。
5. **file/audio/video 拒绝**：只在单测覆盖（发送这类附件的宿主路径未在 live 构造）；live 用例 7 只覆盖图片。
6. **Messages / Responses 协议面**：不在 P0，未做。
7. `npm test` 的 242 条是集成分支累计值；本票自身新增 1 条（linkUrl 归一化）。
